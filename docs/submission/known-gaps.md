# Known gaps

Two kinds of gap are listed. Part 1 is web calls that no service answers yet. Part 2 is system-level gaps
that no single call shows. Status words: **open** (not built), **closed** (built and checked against the
code), **partial** (the core exists, the stated part does not).

## Part 1: web calls without a service endpoint

The web BFF (`apps/web/app/api/[...path]/route.ts`, logic in `apps/web/src/layers/shared/api/bff/`) calls the
services through the reconciled contracts. Where no service has an endpoint, the browser adapter
(`createHybridApi`, `NEXT_PUBLIC_MIO_API=http`, the compose default; `MIO_API=mock` builds the all-mock app) keeps the mock adapter **for that call only**. A failed real
call is never replaced by the mock. The list of mock-answered calls is `GAP_CALLS` in
`apps/web/src/layers/shared/api/mio/hybrid.ts`; this table is its documentation, and it must be updated when
that list changes.

### Not gaps (the call exists and is wired)

Spin (`POST /v1/spins`, `segment_index/segment_label/reward_coins`), `GET /v1/me/spins`, balance
(`GET /v1/me/balance`, `available`), redemption (`POST /v1/redemptions` 202, 409 `insufficient_funds`, store
status words), store items, operator signup, plans, payment attempt and cancel (with `Idempotency-Key`), usage,
invoices, acting (`POST /v1/auth/acting`, token kept server-side), audit trail.

## Part 2: system-level gaps

| id   | Gap                                                             | Status  | What it means                                                                                                                                                                                                                                                                               |
| ---- | --------------------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S-1  | No missed-event replay                                          | open    | The websocket delivers at most once. An event emitted while a client is disconnected is lost, and the client resyncs over REST after reconnecting. Socket.IO `connectionStateRecovery` is off on purpose (it replays before auth middleware runs). The authenticated journal replay is next |
| S-2  | Stripe exists only as an interface                              | open    | `PaymentProvider` is a port; the `fake` provider is built and used. `StripePaymentProvider` is a stub, selected only when `STRIPE_SECRET_KEY` is set, and every method throws. No charge, refund or hosted checkout against Stripe was run                                                  |
| S-3  | The production identity provider is not chosen                  | open    | Staff and operators sign in through the Firebase Auth Emulator behind `IdentityProvider`. Behaviours that differ in production (rate limits, email delivery, claim size) are untested. Refresh tokens are not built: an access token lives 15 minutes                                       |
| S-4  | Deckhand deploy and Varta wiring are described, not run         | open    | `.deckhand/deploy.yml` and the architecture docs describe a blue-green deploy and Varta ingestion. No deploy was run here, no Varta instance received a log line, and no service emits product events yet (the event contract and logger function exist)                                    |
| S-5  | No rate limiting                                                | open    | No per-tenant, per-principal or per-IP limit exists in any service. The Redis counters named in early design notes are not built                                                                                                                                                            |
| S-6  | Redis balance projection is optional and off in default compose | partial | Payments reads its cache only when a Redis client is configured; the default compose file gives Redis to engagement only. Balance reads then come from Postgres. Command paths always read Postgres                                                                                         |
| S-7  | Reconciliation and dead-letter queues have no alerting          | partial | A mismatch is recorded and the CLI exits 1; a dead-letter queue holds messages until someone replays them (`node dist/dlq-replay.js`). Nothing pages a person                                                                                                                               |
| S-8  | Rejected ingest events are not counted                          | partial | A rejection is answered with a code and logged with the tenant slug. There is no counter metric and the body is not stored                                                                                                                                                                  |
| S-9  | Per-service deployment secrets                                  | open    | Isolation at database level is built (owner and app roles, RLS). Secret delivery per service is not, and is not claimed                                                                                                                                                                     |
| S-10 | The interactive architecture diagrams are stale in places       | partial | The Mermaid copies match the code. The archify `*.json` and `*.html` files still show earlier redemption state names and the earlier spin-credit arrow until re-rendered                                                                                                                    |
